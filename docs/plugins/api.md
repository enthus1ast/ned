## nedplugin

nedplugin — what a ned plugin imports.

A plugin is a folder with a `plugin.nims` (NimScript: ned runs the NimScript plugins together in one `nim e`
process — compiled when `plugins.native` says so: auto compiles a set of plugins you keep) or a `plugin.nim`
(full Nim: ned compiles it into a program of its own — the whole standard library, threads, sockets). Its
top-level code runs once when it starts: it registers commands, keys, events, languages, formatters, language
servers, completions, hover, code actions, symbols, snippets, tools for the assistant, views in the Plugins dock,
vim mappings … with the procs below. ned calls them back.

```nim
import nedplugin

command "Upper-case the line", "ctrl+alt+u":
  let b = current()
  let p = b.cursor
  b.replace(lineRange(b, p.line), b.line(p.line).toUpperAscii)

onSave("*.md") do (ev: Event):
  message("saved " & ev.path)
```

Lines and columns count from 0; a column is a byte offset in the line (UTF-8). A `Range` goes from `start` up to
`stop` (`stop` itself not included). ned and the plugins talk in JSON lines over the host's stdin and stdout —
`echo` in a plugin goes to its log (the Plugins dock).

How the calls go, both ways:

- ned calls a plugin back (a command, an event, a completion …) one call at a time for each process: while one
  callback runs, the other plugins in the same process wait. Keep callbacks short; run slow programs with
  `shellAsync`, and give a slow plugin a process of its own (`plugins.alone`).
- Every proc below that asks ned something sends it a request and waits for the answer: a few milliseconds
  under `nim e`, about 0.3 ms compiled. Ask for many lines at once (`b.lines`), not one request a line.
- All the edits a plugin makes in one callback are one undo step.
- A request ned refuses raises `ValueError` with ned's reason: a tab that was closed, a read-only file, a
  permission you did not give. An exception that leaves a callback is that call's error: it is written in the
  plugin's log and shown in the status line, and the plugin goes on running.
- ned waits for some callbacks before it goes on — `onBeforeSave`, a NimScript formatter, a text object, code
  actions — up to `plugins.timeoutMs` (1500 ms; 1 s for code actions). It does not wait for the others.

### the basic types

#### type `Pos`

```nim
type Pos = object
```

A place in a file: a line and a column, both counted from 0. The column is a byte offset in the line's UTF-8 text, not a count of characters: in `"né x"` the `x` is at column 4. Nim's `find` and string indexes count the same way, so their numbers can be used as they are. Make one with `pos(line, col)`.

```nim
let top = pos(0, 0)              # the start of the file
let here = current().cursor      # where the cursor is
```

| field | type | |
|---|---|---|
| `line, col` | `int` | its line (from 0) and column (from 0, a byte offset in the line) |

#### type `Range`

```nim
type Range = object
```

Some text of a file: from `start` up to `stop`, `stop` itself not included. An empty range (`start` == `stop`) is a place between two characters: replacing it inserts there. Make one with `rng(a, b)`, `b.lineRange(line)` or `b.wholeLines(first, last)`; `noRange()` is no range at all.

```nim
let word = rng(pos(2, 4), pos(2, 9))   # line 3, columns 4 to 8
```

| field | type | |
|---|---|---|
| `start, stop` | `Pos` | from start up to stop (stop not included) |

#### type `Buf`

```nim
type Buf = object
```

A tab of ned's: a file, an unsaved new file, or a tab a plugin made (`newTab`). It is only a number — every question about it (`b.text`, `b.cursor` …) asks ned, so the answer is the file as it is now. Once its tab is closed, asking about it raises `ValueError` ("no such buffer").

| field | type | |
|---|---|---|
| `id` | `int` | ned's number for it, the same while its tab is open (-1: none — `valid` is false) |

#### type `Event`

```nim
type Event = object
```

What an event is about, given to each event's callback (`onOpen`, `onSave` …): the file, its path and its language.

| field | type | |
|---|---|---|
| `buf` | `Buf` | the file (onQuit: none, id -1) |
| `path, lang` | `string` | the file's path ("" for a tab that is not a file) and its language id ("nim", "zig" …) |

#### type `Edit`

```nim
type Edit = object
```

One change to a file: the text of `range` replaced with `text`. A `Fix` is a list of them; ned applies a list from the last edit back to the first, so each range is a range of the text before any of them.

| field | type | |
|---|---|---|
| `range` | `Range` | what it replaces (empty: an insertion at its start) |
| `text` | `string` | what goes there (it may have line ends; "" deletes) |

#### type `Fix`

```nim
type Fix = object
```

A change Alt+Enter offers in its Quick fixes list: the title it shows, and the edits it makes when chosen — all of them one undo step. A problem's `fixes` and what `codeActions` gives are lists of these.

```nim
Fix(title: "Use two spaces", edits: @[Edit(range: rng(pos(3, 0), pos(3, 1)), text: "  ")])
```

| field | type | |
|---|---|---|
| `title` | `string` | what the list shows ("Use `foo`"); a fix without a title is left out |
| `edits` | `seq[Edit]` | the changes it makes (one undo step); a fix without edits is left out |

#### type `Problem`

```nim
type Problem = object
```

Something wrong in a file, as a plugin reports it with `setProblems`: the text is underlined, the Problems panel lists it, the gutter marks it, Alt+N and Alt+P go from one to the next, and Alt+Enter on its line offers its fixes.

```nim
Problem(range: b.lineRange(4), severity: 2, message: "a line over 100 characters",
        fixes: @[Fix(title: "Cut it", edits: @[Edit(range: rng(pos(4, 100), pos(4, 140)))])])
```

| field | type | |
|---|---|---|
| `range` | `Range` | the text it is about (an empty range: the place) |
| `severity` | `int` | 1 error, 2 warning (0 is taken as 2), 3 information, 4 hint |
| `message` | `string` | what is wrong, in the Problems panel and the hover |
| `fixes` | `seq[Fix]` | what Alt+Enter offers on its line (none: no fix) |

#### type `LangSpec`

```nim
type LangSpec = object
```

A language for `language`: a new one, or changes to one ned has. A new language is coloured by ned's generic lexer with the words and rules given here; for one ned has (by its id or its name), the word lists are added to its own and the other fields given take the place of its. Every field may be left out. They are the fields of the `languages` setting, and yours win over a plugin's, field by field.

```nim
language("just", LangSpec(name: "Just", files: @["justfile"], lineComment: "#",
                          keywords: @["set", "alias", "export"], nameChars: "-"))
```

| field | type | |
|---|---|---|
| `name` | `string` | its name in the status bar and the language list ("Zig"; "": its id) |
| `extensions, files` | `seq[string]` | its files: by extension, no dot (@["zig", "zon"]), or by whole name (@["build.zig"]) |
| `lineComment` | `string` | its line comment ("//", "#"): what Ctrl+/ and `b.lineComment` use |
| `blockComment` | `seq[string]` | its block comment, start and end: `@["/*", "*/"]` (two strings, or none) |
| `quotes` | `string` | the characters a string starts and ends with (`"\"'"`; a new language: both) |
| `keywords, types, constants, builtins` | `seq[string]` | words coloured as keywords, types, constants, builtins |
| `functionWords, classWords` | `seq[string]` | the words before a function's or a class's name (@["fn"]): the outline finds the names after them |
| `indentAfter` | `seq[string]` | a line that ends in one of these indents the next: characters ({ ( [ : =) or words (@["do", "then"]) |
| `dedent` | `string` | typing one of these characters at a line's start takes a level off ("})]") |
| `indentSize` | `int` | spaces to an indentation level (0: not set — 2 for a new language) |
| `tabs` | `bool` | indent with tabs (false: not set; `filetype(lang, tabs = 0)` turns tabs off) |
| `run` | `string` | the command F5 runs; $file $dir $name $root $tmp in it are replaced ("zig run $file") |
| `build, check` | `string` | the commands of Build (Alt+B) and of the check on save (the same $ words) |
| `pairs` | `string` | `"()[]{}\"\""` — what typing an opening one closes (a new language: `()[]{}""''`) |
| `dedentWords` | `seq[string]` | a line that becomes one of these words alone goes one level out (@["end"]) |
| `nestedComments` | `bool` | a block comment may hold another (`/* /* */ */` — Odin, Haskell's {- -}) |
| `tripleQuotes` | `bool` | `"""…"""` strings, over several lines |
| `multilineStrings` | `bool` | a "…" string (or a backquoted one) not closed on its line goes on below (Gleam, Odin's raw) |
| `charLiterals` | `bool` | 'a' is a character (not a quote of a string) |
| `capitalTypes` | `bool` | a Capitalised word is a type (an ALL-CAPS one a constant) |
| `decorators` | `bool` | @name is coloured as an attribute |
| `docComment` | `string` | a doc comment's line start ("///", "--\|"), coloured as documentation |
| `docBlockComment` | `seq[string]` | a doc block comment: `@["/**", "*/"]` |
| `nameChars` | `string` | characters a name may have after its first letter, besides letters, digits and _ ("?!" Elixir, "'" Haskell, "-" Lisp) |

#### `pluginOf`

```nim
proc pluginOf(file: string): string
```

The plugin a source file belongs to: the name of the plugin whose folder holds it (ned names the plugins' folders in `NED_PLUGIN_DIRS` when it starts their process), or — for a file run on its own — its folder's name. The registering templates use it to know whose a registration is; a plugin seldom needs it.

### JSON ⇄ the types

#### `%`

```nim
proc `%`(p: Pos): JsonNode
```

The position as ned's JSON, `{"line": 3, "col": 0}` — for a tool's answer or a file of your own.

#### `%`

```nim
proc `%`(r: Range): JsonNode
```

The range as ned's JSON, `{"start": {…}, "stop": {…}}`.

#### `%`

```nim
proc `%`(e: Edit): JsonNode
```

The edit as ned's JSON, `{"range": {…}, "text": "…"}`.

#### `%`

```nim
proc `%`(f: Fix): JsonNode
```

The fix as ned's JSON, `{"title": "…", "edits": […]}`.

#### `%`

```nim
proc `%`(p: Problem): JsonNode
```

The problem as ned's JSON (a severity of 0 becomes 2, a warning).

#### `pos`

```nim
func pos(line, col: int): Pos
```

A position: `line` and `col`, both from 0; `col` is a byte offset in the line.

```nim
b.setCursor(pos(0, 0))         # to the start of the file
```

#### `rng`

```nim
func rng(a, b: Pos): Range
```

The range from `a` up to `b` (`b` itself not included). `rng(p, p)` is empty: a place to insert at.

```nim
b.replace(rng(pos(0, 0), pos(0, 4)), "Done")   # the first four bytes of the first line
```

#### `isEmpty`

```nim
func isEmpty(r: Range): bool
```

True when the range holds no text: `start` is at `stop` (or after it on the same line), or it is `noRange()`.

#### `noRange`

```nim
func noRange(): Range
```

No range at all (its start is at line -1): what a text object returns when there is none at the cursor, and what a helper of yours can return for "not found". `isEmpty` is true for it.

### buffers: the text

#### `current`

```nim
proc current(): Buf
```

The file being edited: the tab in front. In a callback ned says which it is with the call, so this costs no request. Its id is -1 (`valid` false) when there is none.

```nim
let b = current()
message(b.path & ": line " & $(b.cursor.line + 1))
```

#### `openFile`

```nim
proc openFile(path: string, line = -1, col = -1): Buf
```

Opens a file in a tab — or goes to its tab when it is open — and brings it to the front. `path` is absolute or relative to the project's folder. `line` and `col` (from 0) put the cursor there; -1 leaves it where it was. Returns the file's `Buf`, or one with id -1 (`valid` false) when it cannot be opened.

```nim
let b = openFile("src/app.nim", 41)     # line 42, as people count
```

#### `newTab`

```nim
proc newTab(title, text: string, lang = ""): Buf
```

Opens a tab of the plugin's own with `text` in it — not a file until it is saved: a response, generated code, a report — and brings it to the front. `title` is the name on the tab. `lang` is a language's id or name ("json", "Markdown") for its colours ("": plain text). A tab of that title that is already open is used again, its text replaced — unless it has edits that are not saved: then it comes to the front as it is (check `b.dirty`). To make saving it do something of yours, give it a language of your own and `onSaveTab`.

```nim
let b = newTab("Report", lines.join("\n"), "markdown")
```

#### `clipboard`

```nim
proc clipboard(): string
```

The clipboard's text: what Ctrl+V would paste (the system's clipboard; what was copied in ned when the system's cannot be read). Needs the "clipboard" permission.

#### `setClipboard`

```nim
proc setClipboard(text: string)
```

Puts `text` on the clipboard — the system's and ned's own. Needs the "clipboard" permission.

#### `buffers`

```nim
proc buffers(): seq[Buf]
```

Every tab's file, in the order of the tabs: files, unsaved new files and plugins' tabs.

```nim
for b in buffers():
  if b.dirty: log(b.title & " has changes not saved")
```

#### `valid`

```nim
proc valid(b: Buf): bool
```

True for a file ned has: false for the `Buf` that `current()` or `openFile` give when there is none (id -1). It asks nothing: a tab closed since still looks valid, and asking about it raises `ValueError`.

#### `path`

```nim
proc path(b: Buf): string
```

The file's path, absolute ("" for a tab that is not a file).

#### `lang`

```nim
proc lang(b: Buf): string
```

Its language's id, lower case: "nim", "python", "markdown", "plaintext" … (a plugin's language has the id it was registered with). The status bar shows a file's language.

#### `lineCount`

```nim
proc lineCount(b: Buf): int
```

How many lines it has. An empty file has one, empty, line: it is never 0.

#### `line`

```nim
proc line(b: Buf, i: int): string
```

Line `i` (from 0) without its line end; "" past the end. Reading a file line by line costs two requests, not one a line, while it does not change: the plugin keeps a copy of its lines (ned 6.29).

#### `lines`

```nim
proc lines(b: Buf, first = 0, last = -1): seq[string]
```

Lines `first` to `last`, both included (`last` -1, or past the end: to the end), without their line ends — one request for all of them.

```nim
for i, l in b.lines:
  if l.len > 100: log("line " & $(i + 1) & " is long")
```

#### `text`

```nim
proc text(b: Buf): string
```

The whole text: its lines joined with "\n".

#### `textIn`

```nim
proc textIn(b: Buf, r: Range): string
```

The text in the range, its lines joined with "\n". A position past a line's end or the file's end is taken as that end.

#### `setText`

```nim
proc setText(b: Buf, s: string)
```

Replaces the whole text with `s`. ned changes only the lines that differ, so the cursor, the folds and the undo stay sensible. One undo step with the plugin's other edits in this call. Raises `ValueError` for a file that cannot be changed (read-only).

#### `replace`

```nim
proc replace(b: Buf, r: Range, s: string)
```

Replaces the text in `r` with `s` (which may have line ends); an empty range inserts. All the edits a plugin makes in one callback — a command, an event, a fix, a timer — are one undo step. Positions out of the text are moved into it. An edit moves the text after it: when making several, go from the last place to the first. Raises `ValueError` for a file that cannot be changed (read-only).

```nim
b.replace(b.lineRange(0), "# " & b.line(0))
```

#### `insert`

```nim
proc insert(b: Buf, p: Pos, s: string)
```

Inserts `s` at `p` (as `replace(rng(p, p), s)`).

#### `delete`

```nim
proc delete(b: Buf, r: Range)
```

Removes the text in `r` (as `replace(r, "")`).

#### `cursor`

```nim
proc cursor(b: Buf): Pos
```

Where the cursor is (the main one, with multiple cursors). In vim's normal mode, the character the block cursor is on starts there.

#### `setCursor`

```nim
proc setCursor(b: Buf, p: Pos)
```

Moves the cursor to `p` (into the text when `p` is out of it): one cursor, nothing selected. It does not bring the file to the front: `openFile(b.path, line, col)` does that.

#### `selection`

```nim
proc selection(b: Buf): Range
```

The main cursor's selection, from its start to its end whichever way it was made; empty (`start` == `stop`: the cursor) when nothing is selected. In vim's visual mode the character under the cursor is in it, and in visual-line mode the whole lines are (without the last one's line end).

```nim
let r = b.selection
let s = if r.isEmpty: b.wordAt(r.start) else: b.textIn(r)
```

#### `vimMode`

```nim
proc vimMode(): string
```

Vim's mode: "normal", "insert", "visual", "visual line" or "replace"; "" when vim keys are off (`editor.vimMode`).

#### `selections`

```nim
proc selections(b: Buf): seq[Range]
```

Every cursor's selection — one for each of multiple cursors (one with a single cursor) — as `selection` gives them. They are not in the file's order: sort them, and edit from the last one to the first, so the ranges not yet edited stay where they are. ned's *Add cursor below* (Alt+J) and *Add cursor above* (Alt+K) make more cursors.

#### `select`

```nim
proc select(b: Buf, r: Range)
```

Selects `r`: one cursor, at `r.stop`, the selection going back to `r.start`.

#### `wordAt`

```nim
proc wordAt(b: Buf, p: Pos): string
```

The word at `p` — the letters, digits and _ around it — or "" when there is none.

#### `dirty`

```nim
proc dirty(b: Buf): bool
```

True when it has changes that are not saved.

#### `save`

```nim
proc save(b: Buf)
```

Writes it to its file, as Ctrl+S does — but without the plugins' save events (`onBeforeSave`, `onSave`), so a save in an event cannot start another. Saving a file outside the project (and outside the plugin's data folder) needs the "files" permission.

#### `closeTab`

```nim
proc closeTab(b: Buf)
```

Closes its tab. A file with changes not saved asks you first (and stays open if you say no); a tab that is not a file closes without asking.

#### `markSaved`

```nim
proc markSaved(b: Buf)
```

Counts it as saved: no ● on its tab, no question when it closes. For a tab of the plugin's own, once `onSaveTab`'s callback has done what saving means for it.

#### `title`

```nim
proc title(b: Buf): string
```

The name on its tab (a file's: its file name).

#### `setTitle`

```nim
proc setTitle(b: Buf, title: string)
```

Renames a tab that is not a file (one of `newTab`'s). Raises `ValueError` for a file's tab: its file names it.

#### `indentUnit`

```nim
proc indentUnit(b: Buf): string
```

What one level of indentation is in this file: "  ", "    " or "\t" — from the file itself, its language and your settings.

#### `lineComment`

```nim
proc lineComment(b: Buf): string
```

Its language's line comment ("#", "//", "--"); "" when the language has none.

#### `lineRange`

```nim
proc lineRange(b: Buf, line: int): Range
```

Line `line` without its line end, as a Range: from column 0 to the line's length.

```nim
b.replace(b.lineRange(l), b.line(l).strip(leading = false))   # its trailing spaces gone
```

#### `wholeLines`

```nim
proc wholeLines(b: Buf, first, last: int): Range
```

Lines `first` to `last` with their line ends, as a Range: from the start of `first` to the start of the line after `last` (to the end of the file when `last` is the last line). Deleting it removes the lines — but the file's last line has no line end of its own, so deleting it alone leaves an empty line: to remove it, start the range at the end of the line before it.

```nim
b.delete(b.wholeLines(4, 6))    # lines 5, 6 and 7 gone
```

### keys: what waits, what the next key does (which-key)

#### type `KeyMap`

```nim
type KeyMap = object
```

A key, or keys, that a plugin uses (or your `keys` setting): what `keyMaps` lists, for a box of what can be typed next.

| field | type | |
|---|---|---|
| `mode` | `string` | n v (vim mappings), op (an operator), obj (a text object), key (any keymap) |
| `keys` | `string` | as given: `<leader>f`, `gc`, `ie`, `ctrl+alt+u` |
| `desc` | `string` | what it does ("": not said; for a command's key, its title) |
| `lang` | `string` | only in files of this language ("" every file) |
| `plugin` | `string` | whose ("" yours) |

#### `pendingKeys`

```nim
proc pendingKeys(): tuple[keys, mode: string]
```

The keys typed that wait for more ("" when none waits) and the mode, as `onKeysWaiting` gives them: "n" (vim's normal mode), "v" (visual), "o" (an operator waits for its motion: "d", "gc"), "obj" (… for its text object, after i or a: "di"), "emacs" or "helix". The keys are written as vim writes them — `g`, `<leader>f`, `<C-a>` — and emacs's as `C-x`. ("", "") while a prompt or a list is open.

#### `showKeyHints`

```nim
proc showKeyHints(title: string, hints: openArray[(string, string)]): bool
```

Shows a box above the status bar, titled `title`, with each key of `hints` and what it does: the keys that may come next. ned closes it when the keys waiting change (one is typed, Esc); tapping a key in it types it. Returns false, and shows nothing, when no keys wait now.

```nim
onKeysWaiting(300) do (keys, mode: string):
  if keys == "<leader>":
    discard showKeyHints("leader", [("f", "find a file"), ("g", "git")])
```

#### `hideKeyHints`

```nim
proc hideKeyHints()
```

Closes the box of `showKeyHints` (ned closes it by itself when the keys waiting change).

#### `keyMaps`

```nim
proc keyMaps(): seq[KeyMap]
```

Every key the plugins use — vim mappings, operators, text objects, `keyIn`'s keys, commands' keys — and the commands on keys in your `keys` setting, each with what it does: what a which-key box lists.

### talking to you

#### `message`

```nim
proc message(s: string)
```

Shows `s` in the status line, until the next message.

#### `warn`

```nim
proc warn(s: string)
```

Shows `s` in the status line as a warning, in the warning colour.

#### `toast`

```nim
proc toast(s: string)
```

Shows a note in a corner of the screen that goes away by itself after a few seconds — for something that ended in the background, or a reminder.

#### `pick`

```nim
proc pick(title: string, items: openArray[string], details: openArray[string] = []): int
```

Shows a list to choose from, titled `title`, and waits until you choose: the index of the item chosen (from 0), or -1 when you cancel (Esc). `details`: dimmer text beside each item (one for each item, or none). The plugin waits meanwhile; ned does not. While ned waits for the plugin (an `onBeforeSave` event, a NimScript formatter, a text object, code actions), or while another plugin asks you something, it returns -1 at once.

```nim
let i = pick("Which case?", ["UPPER", "lower", "Title"])
if i >= 0: message("you chose " & $i)
```

#### `ask`

```nim
proc ask(prompt: string, default = ""): string
```

Asks for a line of text: a prompt with `default` typed in it, waiting for Enter. Returns what you typed, or "" when you cancel — and "" at once while ned waits for the plugin, as `pick` does.

```nim
let name = ask("New name:", b.wordAt(b.cursor))
```

#### `confirm`

```nim
proc confirm(question: string): bool
```

Asks a yes / no question ("… (y/n)"): true when you answer y. Returns false at once while ned waits for the plugin, as `pick` does.

#### `runCommand`

```nim
proc runCommand(name: string)
```

Runs a command of ned's palette by its name, as you would: "Save", "Format document", "Add cursor below" … (every name is in docs/reference/commands.md; the plugins' commands are there too). Nothing happens for a name ned does not have. A command that runs programs or changes settings — one with run, build, test, terminal, git, format, setting … in its name — needs the "shell" permission.

#### `shell`

```nim
proc shell(cmd: string, dir = ""): tuple[output: string, code: int]
```

Runs `cmd` with the shell in `dir` (else the project's folder) and waits for it: its output — standard output and error together, without the line end at its end — and its exit code. Needs the "shell" permission (`ValueError` without it). The plugin's process waits until the command ends, and so do the other plugins in that process: use `shellAsync` for anything slow. Put a path in a command with `quoteShell`.

```nim
let (o, code) = shell("git rev-parse --abbrev-ref HEAD")
if code == 0: status("⎇ " & o)
```

#### `shellAsync`

```nim
proc shellAsync(cmd: string, cb: proc(output: string, code: int), dir = "")
```

Runs `cmd` in the background — in `dir`, else the project's folder — and calls `cb` with its output (standard output and error, without the line end at its end) and its exit code when it ends. The plugin goes on meanwhile (`shell` waits): a build, a request, anything slow. `cb` is a call of ned's like a command: its edits are one undo step. Needs the "shell" permission (`ValueError` without it). When the plugin's process stops before the command ends, `cb` is not called.

```nim
shellAsync("git fetch --quiet") do (output: string, code: int):
  toast(if code == 0: "fetched" else: "git fetch: " & output)
```

#### type `RegexMatch`

```nim
type RegexMatch = object
```

One match of `regexMatches`: where it is in the text, in bytes, and where each of its groups is.

| field | type | |
|---|---|---|
| `start, stop` | `int` | the match: `text[start ..< stop]` (byte offsets; stop not in it) |
| `groups` | `seq[(int, int)]` | each group's (start, stop), from group 1; (-1, -1) for a group that matched nothing |

#### `regexMatches`

```nim
proc regexMatches(pattern, text: string, ignoreCase = false, limit = 10000): seq[RegexMatch]
```

Every match of `pattern` in `text` (`limit` at most, up to 100000), by ned's own regular expressions — its search's: `.` `[a-z]` `\d` `\w` `\s` `\b` `*` `+` `?` `{n,m}`, lazy `*?`, groups `(…)` `(?:…)`, `|`, `^` `$`. With `ignoreCase`, upper and lower case match each other. Raises `ValueError` with ned's words for a pattern that is not one. NimScript has no regular expressions of its own: this is one request to ned.

```nim
for m in regexMatches(r"(\w+)@(\w+)\.org", text):
  let (a, e) = m.groups[0]
  log("a name: " & text[a ..< e])
```

#### `regexReplace`

```nim
proc regexReplace(pattern, text, replacement: string, ignoreCase = false): tuple[text: string, count: int]
```

`text` with each match of `pattern` replaced by `replacement`, and how many matches there were. In `replacement`, $0 is the match, $1 … $9 and ${12} its groups, \n and \t a line end and a tab. Raises `ValueError` for a pattern that is not a regular expression.

```nim
let (t, n) = regexReplace(r"(\d+)-(\d+)", "pages 3-7", "$1 to $2")   # ("pages 3 to 7", 1)
```

```nim
proc unixTime(): float
```

Now, in seconds since 1970 (UTC), with fractions — ned's clock: NimScript has none of its own. For how long something took, or since when.

#### `localTime`

```nim
proc localTime(): string
```

Now on your clock, as "2026-10-24 14:03:05" (year-month-day hours:minutes:seconds): `localTime()[0 ..< 10]` is today's date.

#### type `IndentStyle`

```nim
type IndentStyle = object
```

How the indentation of each line looks — dots in its spaces, a mark for tabs, a colour for each level, a band where it is wrong. A plugin gives it once with `indentStyle`, and ned draws it as it draws each line: nothing is sent for each line, so a big file costs no more than a small one (ned 6.29). Each mark is one character.

```nim
indentStyle(IndentStyle(dot: "·", levels: @["warn", "add", "info", "accent"], wrongColor: "error"))
```

| field | type | |
|---|---|---|
| `dot` | `string` | a mark in each space of the indentation, up to the first letter ("·"; "": none) |
| `dotColor` | `string` | its colour: guide (the default), hint, accent, info, warn, add, del, error or "#rrggbb" |
| `tab` | `string` | a mark at the first column of a tab in the indentation ("→"; "": none) |
| `blankLines` | `bool` | a blank line's indentation too: as deep as the code around it |
| `lineEnd` | `string` | a mark after the end of each line ("¬"; "": none) |
| `levels` | `seq[string]` | a colour for each level of indentation, round again after the last (as dotColor) |
| `levelStyle` | `string` | how the levels show: "background" (bands: the default), "guides" (the │ of each level in its colour) or "dots" (the dots in it) |
| `wrongColor` | `string` | indentation that is not whole levels (3 spaces where a level is 2): its band ("": not marked) |
| `langs` | `seq[string]` | only in these languages ("nim", "python" …; empty: every file) |

#### `indentStyle`

```nim
proc indentStyle(s: IndentStyle)
```

Sets this plugin's look for indentation. One for each plugin: a new one takes the place of the last, and `indentStyle(IndentStyle())` takes it away. When several plugins give one, the first plugin's dot, tab mark, line-end mark and level colours each win. Selections, search matches and highlights keep their own colours; it is not drawn in diffs, nor with `ui.accessible` on.

The text of a file of this plugin's data folder, or "" when there is none. `name` is relative to `dataDir()` — "lists.json", "2026-10/day.log"; a name that is absolute, has "..", ends in "/" or is over 200 bytes raises `ValueError`.


#### `appendData`

```nim

```

Adds `text` at the end of a file of this plugin's data folder (made when there is none): a log. It needs no permission.

#### `permission`

```nim
proc permission(what, why: string)
```

Says what this plugin needs beyond editing, and why. `what` is one of:

- "shell": run programs — `shell`, `shellAsync`, `runInTerminal`, a command of ned's that runs programs (`runCommand`), NimScript's `exec` and `gorgeEx`, std/osproc
- "files": change files — `writeFile`, `mkDir`, `mvFile`, `rmFile`, `removeFile` …, saving a file outside the project (its own data needs none: `writeData`)
- "clipboard": `clipboard` and `setClipboard`
- "network": a plugin in full Nim's sockets (std/net, std/httpclient …)

`why` is what ned shows you when it asks. ned reads these lines, and what the source uses, before the plugin runs, and asks you once; a call that was not allowed raises `ValueError`. Nothing happens when this runs: write it in the top-level code, on one line, with two plain strings. Code ned cannot read ahead (`{.importc.}`, `{.emit.}`, a module from outside the plugin's folder) counts as asking for everything.

```nim
permission("shell", "runs git to show who changed the line")
```

#### `allowed`

```nim
proc allowed(what: string): bool
```

True when you allowed this plugin `what`: "shell", "network", "files" or "clipboard" (false for any other word). For a kinder word than the error when it was not allowed.

#### `pluginDir`

```nim

```

The plugin's own folder, where its plugin.nims or plugin.nim is: for files that come with it (`readFile(pluginDir() / "words.txt")`).

#### `log`

```nim

```

Writes `s` as a line of the plugin's log (the Plugins dock); `echo` writes there too. A line over 400 bytes is cut, and the dock keeps the last few hundred lines.

### registering: what the top-level code of a plugin does

#### `command`

```nim
template command(title: string, body: untyped)
```

A command: `title` is its name in the palette (Ctrl+E), in the Plugins dock under the plugin and in *Plugins: run a plugin's command…* — when ned has a command of that name, the plugin's is called `<plugin>: <title>`. `body` runs each time it is chosen, as one call of ned's: its edits are one undo step. It cannot `return` (it is a template's body): put the work in a proc and call it.

```nim
command "Line count":
  message($current().lineCount & " lines")
```

#### `command`

```nim
template command(title, keys: string, body: untyped)
```

A command on a key too: "ctrl+alt+u", "alt+shift+k", "f9" — ctrl, alt and shift in any order, case does not matter. Your `keys` setting wins over a plugin's key, and a plugin's key over ned's own use of it. Not every terminal passes every combination: the palette always works.

```nim
command "Upper-case the line", "ctrl+alt+u":
  let b = current()
  let l = b.cursor.line
  b.replace(b.lineRange(l), b.line(l).toUpperAscii)
```

#### `onStartup`

```nim
template onStartup(cb: proc(ev: Event))
```

Calls `cb` once, when ned has started and the plugin runs (a plugin with this event starts with ned). `ev.buf` is the tab in front. For reading what the plugin keeps (`readData`) or giving an `indentStyle`.

```nim
onStartup do (ev: Event):
  log("ned started with " & ev.path)
```

#### `onOpen`

```nim
template onOpen(pattern: string, cb: proc(ev: Event))
```

Calls `cb` when a file matching `pattern` is opened, and for the files open when ned starts. ned does not wait for it.

The patterns of every event: `"*"` is every file (and tabs that are not files); `"*.md"` matches the file's name; one with a / (`"src/*.nim"`) its path in the project; `"lang:zig"` its language; several go with commas: `"*.md,*.txt"`. A tab that is not a file matches only `"*"` and `"lang:…"`. Several callbacks for one event — in one plugin or in several — all run, in the order they were registered (ned 6.24).

```nim
onOpen("*.md") do (ev: Event):
  status($ev.buf.lineCount & " lines")
```

#### `onBeforeSave`

```nim
template onBeforeSave(pattern: string, cb: proc(ev: Event))
```

Calls `cb` when a file matching `pattern` is about to be written, and waits for it (`plugins.timeoutMs`, 1500 ms): what it changes in the file is saved. For what belongs in the saved file — trailing spaces gone, a date, a header. Not called for a save the plugin asks for itself (`b.save`), nor while the plugins are starting (ned saves without them, and says so). While ned waits, `pick`, `ask` and `confirm` answer at once.

```nim
onBeforeSave("*.txt") do (ev: Event):
  let t = ev.buf.text
  if t.endsWith(" "): ev.buf.setText(t.strip(leading = false))
```

#### `onSave`

```nim
template onSave(pattern: string, cb: proc(ev: Event))
```

Calls `cb` after a file matching `pattern` was written; ned does not wait. Not called for `b.save()`.

#### `onClose`

```nim
template onClose(pattern: string, cb: proc(ev: Event))
```

Calls `cb` when the tab of a file matching `pattern` was closed. The tab may be gone when it runs: `ev.path` and `ev.lang` say which it was, and asking about `ev.buf` may raise `ValueError`. Its signs, texts and highlights go with it.

#### `onChange`

```nim
template onChange(pattern: string, cb: proc(ev: Event))
```

Calls `cb` when the text of a file matching `pattern` has changed — after a pause in the typing (about 0.4 s), not at every key; once for each file that changed. For what follows the text: problems, signs, a count.

#### `onEnter`

```nim
template onEnter(pattern: string, cb: proc(ev: Event))
```

Calls `cb` when a tab matching `pattern` comes to the front: you switched to it, opened it, or closed the one before it.

#### `onQuit`

```nim
template onQuit(cb: proc(ev: Event))
```

Calls `cb` when ned quits, and waits a moment for it (1.5 s at most): write what the plugin keeps now. `ev.buf` is not set. Only when the plugin's process is running.

```nim
onQuit do (ev: Event):
  writeData("state.json", $state)
```

#### `every`

## nedlsp

nedlsp — a language server in NimScript.

`ned --lsp-bridge server.nims` runs the file with `nim e` and speaks the Language Server Protocol for it on its
stdin and stdout: the file reads one JSON message per line and writes one per line. That command is the server
for ned (a plugin's `languageServerScript`) and for any other editor.

```nim
import nedlsp

onRequest("textDocument/hover") do (params: JsonNode) -> JsonNode:
  let w = wordAt(params)
  if w.len == 0: return newJNull()
  %*{"contents": {"kind": "markdown", "value": "**" & w & "**"}}

serve(%*{"hoverProvider": true})
```

The library keeps the open documents' text (`docText(uri)`), answers initialize, shutdown and exit, and
converts the client's columns (UTF-16 or UTF-8, as agreed) to byte offsets in the line (`byteCol`).

A server is a script of its own: it runs in its own process, with its folder as the current folder, and it
cannot use `nedplugin` (it talks to the editor, not to ned's plugin host). It handles one message at a time,
in the order they come. Its standard output is the protocol's: a line it writes that is not a message (an
`echo` while you debug it) goes to the bridge's standard error, whose last lines ned shows when the server
stops; `showMessage` puts an error or a warning in ned's status line. Try it on its own with
`ned --lsp-bridge server.nims` and a few messages typed in, or from another editor (Helix, Neovim …): its
language client runs `ned` with the arguments `--lsp-bridge /path/to/server.nims`.

#### var `docs`

```nim
var docs: Table[string, string]
```

The open documents' text by their URI ("file:///home/you/a.md"), as the client has it now, unsaved edits too. The library keeps it from didOpen, didChange (whole or in parts) and didClose; read it with `docText`.

#### var `docVersion`

```nim
var docVersion: Table[string, int]
```

The open documents' versions by their URI: the number the client gave with its last didOpen or didChange.

#### var `utf8`

```nim
var utf8 = false
```

True when the client counts columns in bytes (it offered UTF-8 positions at initialize); else it counts UTF-16 code units, the protocol's default. `byteCol`, `clientCol`, `lspRange` and `wordAt` count as it says.

#### `send`

```nim
proc send(j: JsonNode)
```

Writes a message to the client, as one line of JSON (`ned --lsp-bridge` gives it the protocol's framing). The answers to requests and `notify` use it; a server seldom needs it itself.

#### `onRequest`

```nim
proc onRequest(meth: string, cb: proc(params: JsonNode): JsonNode)
```

Answers the client's requests of the method `meth` ("textDocument/hover", "textDocument/completion", "textDocument/definition" …): `cb` gets the request's params and returns its result (`newJNull()` for none). Raise an exception to answer with an error: its message goes to the client. One callback for each method — a second takes the first's place. A request with no callback is answered "not supported". The library answers initialize and shutdown itself (an `onRequest("initialize")` callback is called too, for the client's params). Say what the server answers in `serve`'s capabilities.

```nim
onRequest("textDocument/definition") do (params: JsonNode) -> JsonNode:
  let uri = params["textDocument"]["uri"].getStr
  %*{"uri": uri, "range": lspRange(0, 0, 0, "")}     # (the start of the same file)
```

#### `onNotification`

```nim
proc onNotification(meth: string, cb: proc(params: JsonNode))
```

Takes the client's notifications of the method `meth` ("textDocument/didOpen", "textDocument/didSave", "workspace/didChangeConfiguration" …): `cb` gets their params. For didOpen, didChange and didClose the library has updated `docs` before `cb` runs. An exception in `cb` goes to the client's log (`logMessage`).

```nim
onNotification("textDocument/didSave") do (params: JsonNode):
  check(params["textDocument"]["uri"].getStr)
```

#### `notify`

```nim
proc notify(meth: string, params: JsonNode)
```

Sends the client a notification of the method `meth` with its params: `notify("window/logMessage", %*{"type": 3, "message": "hi"})`.

#### `logMessage`

```nim
proc logMessage(s: string, kind = 3)
```

Writes `s` as a line of the client's log of this server (`kind`: 1 error, 2 warning, 3 information, 4 log): other editors keep one (Neovim's :LspLog); ned does not show it — use `showMessage` for what you must see.

#### `showMessage`

```nim
proc showMessage(s: string, kind = 3)
```

A message the client shows to the person using it (`kind`: 1 error, 2 warning, 3 information). ned shows an error in its status line and as a note in the corner, a warning in its status line, and information not at all.

#### `publishDiagnostics`

```nim
proc publishDiagnostics(uri: string, diagnostics: JsonNode)
```

Sets the document's diagnostics — the problems the editor underlines and lists — in place of the ones sent for it before; an empty array clears them. `diagnostics` is a JSON array of {"range": …, "severity": 1 error · 2 warning · 3 information · 4 hint, "message": "…", "source": "…"}.

```nim
publishDiagnostics(uri, %*[{"range": lspRange(0, 0, 5, line), "severity": 2, "message": "too short"}])
```

#### `docText`

```nim
proc docText(uri: string): string
```

The document's text as the client has it now, its unsaved edits too; "" for one that is not open.

#### `docLines`

```nim
proc docLines(uri: string): seq[string]
```

The document's lines: `docText` split at its line ends ("\n"). Line i is the protocol's line i.

#### `byteCol`

```nim
proc byteCol(line: string, character: int): int
```

Turns the client's column in `line` (a position's "character": UTF-16 code units, or bytes when `utf8`) into a byte offset in the line, as Nim's strings count; past the end gives the line's length.

```nim
let l = docLines(uri)[p["line"].getInt]
let c = byteCol(l, p["character"].getInt)     # l[c] is the character at the position
```

#### `clientCol`

```nim
proc clientCol(line: string, b: int): int
```

Turns a byte offset `b` in `line` into the client's column: for the positions a server sends.

#### `lspRange`

```nim
proc lspRange(line, a, e: int, text: string): JsonNode
```

A range on line `line` (from 0) from byte `a` to byte `e` of `text`, the line's text, as the client counts columns: what diagnostics, hover ranges, locations and edits need.

```nim
let k = l.find("TODO")
if k >= 0: diags.add %*{"range": lspRange(i, k, k + 4, l), "severity": 3, "message": "a TODO"}
```

#### `wordAt`

```nim
proc wordAt(params: JsonNode): string
```

The word (letters, digits, _) at a request's position — params with "textDocument" and "position", as hover, completion and definition have — or "" when there is none.

#### `serve`

```nim
proc serve(capabilities: JsonNode = nil)
```

The server's loop: reads the client's messages and calls the callbacks, one message at a time, until the client says exit. Call it last, at the end of the file. `capabilities` say what the server does, as the protocol's ServerCapabilities — {"hoverProvider": true, "completionProvider": {"triggerCharacters": ["."]}, "definitionProvider": true, "documentSymbolProvider": true} …; the library adds "textDocumentSync" (open and close, changes in parts, saves) when they do not say, and the position encoding the client offered.

```nim
serve(%*{"hoverProvider": true, "completionProvider": {}})
```
